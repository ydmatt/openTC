# CHANGELOG

## 2026-08-01 — v1.0.16

### Fixed

- 修复 `Alt+Enter` 被文件列表的普通 `Enter` 导航提前截获的问题。WPF 发送 `Key.System + Return` 时，文件列表路由会显式保留 Alt 修饰键并交给属性快捷键处理，不再打开文件或进入文件夹。

### Verified

- Release 自动化测试 74/74 通过。

## 2026-08-01 — v1.0.15

### Added

- “新建（W）→ 文本文档（.txt）（T）”现在先显示命名窗口。默认名称按 Windows `.txt\ShellNew` 规则取得，初始只选中文件名主体；可保留 `.txt`，也可直接改为 `.bat` 等任意扩展名。

### Fixed

- 新建文件夹或文本文档后，会刷新列表、选中并聚焦新项目；可直接按 `Enter` 继续操作。
- 重命名文件时仅预选文件名主体而保留扩展名；重命名文件夹时仍预选完整名称。
- `Alt+Enter` 现在正确归一化 WPF 的 `Key.System` / `Return` 事件并打开单个选中文件或文件夹的 Windows 属性窗口。
- 升级完成提示同时等待新主窗口完成渲染和工作区初始化，再以新主窗口为 Owner 在前方显示。

### Verified

- Release 自动化测试 74/74 通过，覆盖 `Alt+Enter` 的 WPF 键值归一化及指定文件名、指定扩展名的新建文件操作。

## 2026-07-31 — v1.0.14

### Added

- 文件右键菜单新增“属性（R）”，通过 Windows Shell 打开所选单个文件或文件夹的标准属性窗口；默认快捷键为 `Alt+Enter`。
- “新建（W）”二级菜单新增“文本文档（.txt）（T）”。它读取 Windows `.txt\ShellNew` 规则，使用系统名称与模板/空文件设置创建文本文档，并在重名时自动编号。
- “文件 → 管理工作区方案”新增“重命名…”。重命名保留原方案的完整内容；目标名称已存在时拒绝覆盖，当前使用方案改名后会同步更新默认启动方案。

### Fixed

- 程序内升级成功后，维护程序不再抢先显示完成提示。新版主窗口先完成显示和初始化，再在空闲队列显示“升级完成”提示，不会被压到任务栏后方。

### Verified

- Release 自动化测试 74/74 通过，覆盖 `Alt+Enter` 默认快捷键、右键菜单配置迁移、属性菜单调度、Windows ShellNew 风格文本文档创建及工作区安全重命名。
- 自包含目录已完成独立启动/单实例转发与外部更新器冒烟验证；升级 ZIP 与 `T:\mytc-releases\MYTC-v1.0.14-win-x64` 目录均已按 SHA-256 复核。
